# Filters

Each file is an obfilter selection passed to `ob run --filter <file>`, which
prunes the DAG to the picked stages, modules and parameter combinations.

| File | Runs | Host |
|---|---|---|
| `smoke.yaml` | 10k, CPU modules (scanpy defaults + baseline), seed 0: 8 combinations | any |
| `smoke-gpu.yaml` | 10k, every module, seed 0: 27 combinations | GPU |
| `scaling-gpu.yaml` | 50k and 100k, every module, seed 0: 54 combinations | GPU |
| `cpu-only.yaml` | all sizes, CPU modules, seed 0 | any |
| `noise-pca.yaml` | all sizes, CPU modules: 20 arpack PCA seeds, seed 0 downstream | any |
| `noise-knn.yaml` | all sizes, CPU modules: 20 pynndescent kNN seeds, seed 0 elsewhere | any |
| `noise-cluster.yaml` | all sizes, CPU modules: 20 Leiden seeds, seed 0 upstream | any |

`first` keeps a module's first parameter combination (seed 0), `all` keeps every
seed. The noise filters vary one stage's seed at a time; run them one after the
other into the same `out/` and the seed-0 runs they share are computed once.
Without a filter, every seed list expands against every other (tens of
thousands of jobs per size).

**A filter bypasses the capability gate.** Without a filter, `ob run` on a CPU
host drops the rapids modules (`requires_capabilities: [gpu]`) by itself. With a
filter, every picked module runs, so a filter meant for CPU hosts must leave the
rapids modules out.

## Phase 2 (`phase2/`)

Generated by `scripts/make_filters.py` from `benchmark-phase2.yaml`; never edit them by
hand, and re-run the script after any change to the plan's parameters or commits (the
filters list parameter-combination hashes, which include every value).

| File | Runs |
|---|---|
| `slice-cluster.yaml` | exact PCA and kNN → every Leiden × 5 resolutions × 5 seeds |
| `slice-knn.yaml` | exact PCA → every kNN and its seeds → baseline Leiden, seed 0, 5 resolutions |
| `slice-pca.yaml` | every PCA and its seeds → exact kNN → baseline Leiden, seed 0, 5 resolutions |
| `*-cpu.yaml` | the same without the rapids modules, for CPU hosts |
| `pipelines/<name>-seed<i>.yaml` | one named pipeline at seed *i* (every seeded stage), Leiden at 5 resolutions: baseline, scanpy-defaults, tuned-cpu, all-gpu, hybrid |

A filter picks modules per stage and ob runs every combination across stages, so the five
pipelines cannot share one filter (it would run all their crossings and every combination
of seeds): `scripts/run_pipelines.sh` runs the 25 files one after another into one folder.

    pixi run ob run benchmark-phase2.yaml --filter filters/phase2/slice-cluster.yaml --out-dir out-phase2 --cores 8

Phase 2 runs go to `out-phase2/` (replicates to `out-phase2-rep1/`, ...), never into
Phase 1's `out/`: `analysis/phase2.py` reads every clustering under the folders it is
given, so the two phases must not share one.
